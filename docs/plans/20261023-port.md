# Port

The app comes over from its experiment as a stack of small PRs, bottom up, the way nimbo did: each one builds, is tested and readable on its own, and carries only what it uses. The source is the experiment's last state, already on nimbo with private names removed; this repository starts from an empty history and never sees the experiment's commits.

## Rules for every step

- Port a piece, don't copy it: dependencies come with the step that first uses them (wavo and nimbo by git main); drop what nothing uses yet (no `#![allow(dead_code)]`), rename what reads badly, keep behaviour and tests.
- No generated or binary bulk in git: screenshots go to `target/shots/` (`make shots`), speech fixtures to `target/fixtures/` (`make fixtures`); the only binary is the app icon, one `assets/icon.png`.
- Headless only on the person's Mac: unit tests, `daemon`, `ctl`, `transcribe` with a temp `WAVO_HOME`; never open a window. Windows and real dictation are checked by the person (`make install`).
- One PR per step on github.com/vladkens/wavo-app, the next one after the previous is merged. `make check` and `make test` pass; Codex reviews each PR until a round finds nothing real, at most three rounds, then the person reviews and merges.

## Steps

- [x] 0. Initial commit: `.gitignore`, `.rustfmt.toml`, `Cargo.toml` (`release` and `fast` profiles, both unwinding), `Makefile` (prepare, check, test, build, update, clean), `agents.md`, `readme.md`, `LICENSE`, this plan, a `main.rs` that prints the version.
- [x] 1. CI: GitHub Actions on Linux running `make check` and `make test`.
- [x] 2. Audio: devices, capture (cpal), resampling, VAD, WAV and the recorder; `wavo-app devices` and `record`; tests on the fake microphone.
- [x] 3. Models: not ported; wavo's hub covers the models in the Hugging Face cache and their downloads (`wavo list`, `wavo pull`), later steps use it directly.
- [x] 4. Engine: the `Loader` / `SpeechModel` traits over wavo, the supervisor and engine threads (panics caught, deadlines, stuck threads left behind, cancel), long input in pieces at the model's window by wavo's `transcribe_long` (progress, cancel and a deadline per piece; `wavo::split` before it had one), the engine's input (WAV files read at 16 kHz, silence trimmed by the VAD), the model by wavo's name in the Hugging Face cache or the first one there (`Hub::resolve`, `Hub::downloaded`); `wavo-app transcribe`; tests on `FakeModels` with `Faults`; `make fixtures` and `make test-models` on real models.
- [x] 5. Storage: the data home (`WAVO_HOME`, else nimbo's per-user data directory), settings (JSON, defaults, atomic save), the SQLite history with its audio in day folders (retention, crash recovery).
- [x] 6. Session: the state machine and controller (the observer, settings edits and the key inputs it handles carry `expect(dead_code)` for step 7), the recorder's live signals (trailing quiet, the level meter, the silence watch), the engine's prewarm, idle unload, background jobs, status notify, load error and progress, the control socket (Unix only) with a single-instance lock, `wavo-app daemon` and `ctl` (toggle, start, stop, cancel, status, retranscribe, delete, unload, quit); dictation end to end headless (fake mic, fake engine); `transcribe`'s model and language from the settings; `make unload-memory`; `make test-models` runs only the tests on real models and the fixtures. Once wavo said which languages a model takes and is meant for: no language sent to a model that detects its own (`Model::takes_language`: Parakeet v3), and the "understands X only" note of nothing recognized by a model meant for one (`ModelInfo::langs`), language names by `isolang` (`language::name`).
- [x] 7. macOS shell: `wavo-app gui` (the default command on macOS) on nimbo's app platform: the tray with its menu (warnings, Copy Last Dictation, the model's unload, Quit) and the menu bar icons, the hotkeys, launch at login (`ctl autostart`), the HUD as a nimbo overlay drawn from its platform-free state (tested in the harness), focus and the password-field check through AX, the paste that restores the clipboard (⌘V and the clipboard from nimbo), the microphone's permission, the audio warm-up; a second launch forwards `open-settings` to the first over the control socket; `make bundle`, `run`, `install` with the app icon. The menu, the HUD and the icons build and are tested on Linux too. The step-6 `expect(dead_code)` markers are gone but the history counter of `Update`'s, the History page's.
- [ ] 8. Settings window (opened by the menu's Settings… and History…, `open-settings`, `open-history`, a launch per `Settings::opens_window_at_start`, and the app opened again): General, Models (on wavo's hub: `MODELS` with `family`, `maker`, `card` and `langs`, `Hub::downloaded`, `pull`, `remove`; language names by `language::name`), History (playback through cpal; the session's `reload_model` and `check_model` for the Models page's deletes and downloads; the history's search and pages as `db` getters, with the case `fold` they compare by; local times, shared with the menu's Recent and its model choice; entries are transcriptions only, a failed dictation is the session's last failed recording), About on nimbo, tested headless in the harness; `wavo-app settings`, `make shots`.

Later, each when needed: Windows and Linux (the experiment's settings-only `standalone.rs` is not ported), signing and notarization, releases and the Homebrew cask.
