# Port

The app comes over from its experiment as a stack of small PRs, bottom up, the way nimbo did: each one builds, is tested and readable on its own, and carries only what it uses. The source is the experiment's last state, already on nimbo with private names removed; this repository starts from an empty history and never sees the experiment's commits.

## Rules for every step

- Port a piece, don't copy it: dependencies come with the step that first uses them (wavo by git rev, nimbo by git main); drop what nothing uses yet (no `#![allow(dead_code)]`), rename what reads badly, keep behaviour and tests.
- No generated or binary bulk in git: screenshots go to `target/shots/` (`make shots`), speech fixtures to `target/fixtures/` (`make fixtures`); the only binary is the app icon, one `assets/icon.png`.
- Headless only on the person's Mac: unit tests, `daemon`, `ctl`, `transcribe`, `models` with a temp `WAVO_HOME`; never open a window. Windows and real dictation are checked by the person (`make install`).
- One PR per step on github.com/vladkens/wavo-app, the next one after the previous is merged. `make check` and `make test` pass; Codex reviews each PR until a round finds nothing real, at most three rounds, then the person reviews and merges.

## Steps

- [x] 0. Initial commit: `.gitignore`, `.rustfmt.toml`, `Cargo.toml` (`release` and `fast` profiles, both unwinding), `Makefile` (prepare, check, test, build, update, clean), `agents.md`, `readme.md`, `LICENSE`, this plan, a `main.rs` that prints the version.
- [x] 1. CI: GitHub Actions on Linux running `make check` and `make test`.
- [x] 2. Audio: devices, capture (cpal), resampling, VAD, WAV and the recorder; `wavo-app devices` and `record`; tests on the fake microphone.
- [ ] 3. Models: wavo's catalog with the app's languages, downloads into the Hugging Face cache, GGUF reading; `wavo-app models` and `pull`.
- [ ] 4. Engine: the `Loader` / `SpeechModel` traits over wavo, the supervisor and engine threads (panics caught, deadlines, stuck threads left behind), the engine's input (WAV files read at 16 kHz, silence trimmed by the VAD) and segmenting; `wavo-app transcribe`; tests on `FakeModels` with `Faults`; `make fixtures` and `make test-models` on real models.
- [x] 5. Storage: data paths (`WAVO_HOME`), settings (JSON, defaults, atomic save), the SQLite history with its audio in day folders (retention, crash recovery).
- [ ] 6. Session: the state machine and controller, the recorder's live signals (trailing quiet, the level meter, the silence watch), the control socket, `wavo-app daemon` and `ctl …`; dictation end to end headless (fake mic, fake engine); `make unload-memory`. It is storage's first user: drop the `expect(dead_code)` on `paths`, `settings` and `history` in `main.rs`, and bring the readings of settings (`engine_language`, `unload_after`), the history's change count (`changes`, `mark_changed`) and `now_ms`.
- [ ] 7. macOS shell: tray and menu, the hotkey, focus, keyboard, paste, permissions, the HUD, menu bar icons, launch at login, the audio warm-up, `wavo-app gui` (with `Settings::opens_window_at_start`); `make bundle`, `run`, `install` with the app icon.
- [ ] 8. Settings window: General, Models, History (playback through cpal; the history's search and pages: `page`, `count`, `fold`; local times and the labels of no text and no model, shared with the menu), About on nimbo, tested headless in the harness; `wavo-app settings`, `make shots`.

Later, each when needed: Windows and Linux (the experiment's settings-only `standalone.rs` is not ported), signing and notarization, releases and the Homebrew cask.
